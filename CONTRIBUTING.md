# Contributing

## Clean-room rules (non-negotiable)

Pull requests are rejected, and history rewritten if necessary, if they:

- include or link console firmware, encryption keys, certificates, BIOS or
  system files, or instructions for obtaining them;
- copy from leaked or NDA'd SDKs, documentation or source code;
- include commercial game code, assets or dumps, even as test fixtures;
- were written by someone who has read leaked SDK material for the same area.

Allowed sources: public documentation (for example Switchbrew), the Arm
Architecture Reference Manual, public talks and papers, open-source homebrew,
and observing behaviour of software you wrote yourself.

Test programs go in `guest/src` and must be original code. Their expected
output in `guest/expected` is generated by `scripts/gen-expected.py`, which
models each program in Python without running kestrel; add a model there for
every new program. C programs talk to the console only through `rt.h`, so
they also build natively: on an ARM64 Linux or macOS machine,
`scripts/check-host.sh` runs them on the real CPU and compares with
`guest/expected` (CI does this on both ARM runners). Homebrew-format test
programs go in `guest/src/nro` with their arguments in `name.args`, one per
line; `scripts/build-guest.sh` links them position-independent and
`scripts/make-nro.py` turns them into NROs.

## Workflow

1. `cargo test` and `cargo clippy --workspace --all-targets -- -D warnings` must pass.
2. New instructions need a test whose encoding comes from a real assembler.
   General-purpose instructions (data processing, branches, system
   registers, scalar loads and stores, atomics) get a case in
   `scripts/gen-int-vectors.py`, NEON instructions one in
   `scripts/gen-neon-vectors.py`: add the assembly and a Python model of its
   result written from the Arm ARM, then run the script (needs clang and
   llvm-objdump) to regenerate `interp/int_vectors.rs` or
   `interp/neon_vectors.rs`. Tests that need several instructions go in
   `crates/kestrel-cpu/src/interp/tests.rs`, encoded with
   `llvm-mc --triple=aarch64` and the assembly in a comment.
3. Keep host-specific code behind `cfg(target_arch = ...)` so every host keeps building.
